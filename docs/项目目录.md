# EasyNote 项目目录

| 版本 | 1.0 |
| --- | --- |
| 依据 | PRD v1.0、技术栈基线 2026-11-09、ui设计规范 |
| 形态 | 单 package Electron 应用，单体模块化 |
| 原则 | 进程硬边界；模块软边界；编译期注册；不做运行时插件 |

## 0. 结论

- 单 package、单构建、单部署。不做 monorepo、微服务、动态模块加载。
- `src/main`、`src/preload`、`src/renderer` 是硬边界，禁止互相直接 import 运行时代码。
- 业务按垂直能力切分：一个模块拥有自己的 domain、application、infrastructure、IPC 或 UI。
- 每个模块只通过根目录 `index.ts` 暴露公共 API；其他模块不得深入其内部目录。
- `src/shared` 只放跨进程契约、纯类型、纯函数，不放业务逻辑。
- 新增模块只改组合根与契约，不修改已有模块内部。

## 1. 总体结构

```
┌────────────────────────────── src/renderer ──────────────────────────────┐
│ shell  explorer  editor  tags  search  backlinks  outline  graph  settings │
│                          theme / layout / registry                         │
└───────────────────────────────────┬───────────────────────────────────────┘
                                    │ window.easynote（类型化 API）
┌───────────────────────────────────▼───────────────────────────────────────┐
│ src/preload：api/*，仅 invoke / on / off，不做业务判断                      │
└───────────────────────────────────┬───────────────────────────────────────┘
                                    │ ipcRenderer ↔ ipcMain
┌───────────────────────────────────▼───────────────────────────────────────┐
│ src/main：modules/*  →  platform/*  →  fs / sqlite / watcher / trash / …   │
└───────────────────────────────────┬───────────────────────────────────────┘
                                    │
                          Markdown 文件 + .easynote/index.db
```

| 目录 | 运行环境 | 职责 | 禁止 |
| --- | --- | --- | --- |
| `src/main` | Electron 主进程 | 窗口、文件、SQLite、索引、文件监听、系统回收站、系统主题 | 渲染 UI、直接读渲染进程状态 |
| `src/preload` | 预加载脚本 | 白名单 API 桥接、事件订阅 | 业务逻辑、直接访问数据库或文件 |
| `src/renderer` | 渲染进程 | Vue UI、Tiptap 编辑器、KaTeX、Canvas 图谱 | 直接 import Electron、Node、SQLite |
| `src/shared` | 编译期共享 | IPC 契约、DTO、事件、错误码、纯工具 | 业务实现、进程相关 API |

## 3. 主进程

### 3.1 模块分层

```
src/main/modules/<module>/
├─ domain/            # 纯业务规则、值对象、状态机；不 import Electron / fs / SQLite
├─ application/       # 用例编排；依赖 repository 接口与平台端口
├─ infrastructure/    # SQLite / 文件系统实现；migrations.ts 归模块所有
├─ ipc/               # handler：校验、调用 application、映射 IpcResult
└─ index.ts           # 唯一公开出口：create<Module>Module + 公共 service 类型
```

- `domain` 不依赖任何运行时；可以用纯函数直接测试。
- `application` 不直接 import `electron`、`node:fs`、`better-sqlite3`、`chokidar`。
- `infrastructure` 实现模块自己的 repository；不得写其他模块的表。
- `ipc` 只做参数校验、权限判断、错误映射，不写业务分支。
- 简单模块可以省略 `domain`，只保留 `application` + `infrastructure`；不为层数而层数。

### 3.2 模块清单

| 模块 | 职责 | 数据所有权 | 对外能力 |
| --- | --- | --- | --- |
| `vault` | 首次选库、初始化 `.easynote/`、换库、库元信息 | `vault_meta` | `choose` / `current` / `switch` |
| `folder` | 无限层级目录树、新建、重命名、移动、排序、删除 | `folders` | `tree` / `create` / `rename` / `move` / `delete` |
| `note` | 笔记 CRUD、重命名、复制、标题冲突、frontmatter、原子保存 | `notes` | `read` / `save` / `create` / `rename` / `duplicate` / `delete` |
| `indexer` | 文件监听、全量 / 增量扫描、重建索引、进度 | `file_state` | `start` / `scan` / `rebuild` / `progress` |
| `block` | 块结构、块 ID 分配与匹配、块引用 / 嵌入解析 | `blocks` | `listByNote` / `assignIds` / `resolveRef` / `resolveEmbed` |
| `link` | 双链解析、反向链接、未链接提及、重命名后修链 | `links` | `backlinks` / `unlinked` / `relink` |
| `tag` | 正文 / frontmatter 标签提取、重命名、删除、多选过滤 | `tags`、`note_tags` | `list` / `filter` / `rename` / `delete` |
| `search` | FTS5 查询、命中片段、排序、快速跳转查询 | `notes_fts` | `search` / `quickSwitch` |
| `graph` | 全局 / 局部图数据、深度裁剪、性能阈值 | 无（读模型） | `global` / `local` |
| `settings` | 主题、字号、库路径、快捷键、窗口状态；存用户配置目录 | 用户配置 JSON | `get` / `set` / `watch` |
| `window` | 最小化、最大化 / 还原、关闭、最大化状态事件 | 无 | `minimize` / `toggleMaximize` / `close` / `isMaximized` |

`indexer` 只做流水线编排；块、链接、标签、搜索的写入分别调用对应模块的 application service，不直接跨模块写表。

### 3.3 表归属

| 表 | 所属模块 |
| --- | --- |
| `vault_meta` | `vault` |
| `folders` | `folder` |
| `notes` | `note` |
| `blocks` | `block` |
| `links` | `link` |
| `tags`、`note_tags` | `tag` |
| `notes_fts` | `search` |
| `file_state` | `indexer` |

规则：

- 一个模块只写自己的表；跨模块读取走对方 public service。
- 迁移文件由模块自己提供，`bootstrap/migrations.ts` 汇总后按版本执行。
- 需要跨模块事务时，由 `platform/sqlite/transaction.ts` 提供事务句柄，application service 接受可选事务参数；禁止直接拿其他模块的 repository。
- 索引重建不清空块 ID；复用 `block` 模块的匹配算法。

### 3.4 平台层

| 目录 | 封装 | 使用方 |
| --- | --- | --- |
| `platform/fs` | 原子写入、临时文件、路径越界检查、文件锁 | `vault`、`folder`、`note` |
| `platform/sqlite` | 连接、迁移执行、事务 | 所有主进程模块 |
| `platform/watcher` | chokidar 生命周期、忽略规则、防抖 | `indexer` |
| `platform/trash` | 系统回收站、不可用错误码 | `note`、`folder` |
| `platform/dialog` | 目录选择、系统消息框 | `vault`、删除失败提示 |
| `platform/theme` | `nativeTheme` 监听、系统主题事件 | `settings`、`window` |
| `platform/logger` | 本地日志文件 | `bootstrap`、各模块错误 |

业务模块不直接 import `node:fs`、`better-sqlite3`、`chokidar`；通过 `MainContext` 注入的平台端口使用。`window` 模块的 `infrastructure` 是 Electron 适配层，允许直接调用 `BrowserWindow`。

### 3.5 启动与组合根

```
src/main/index.ts
  └─ bootstrap/lifecycle.ts
      ├─ security.ts
      ├─ context.ts
      ├─ migrations.ts
      ├─ modules.ts
      └─ ipc.ts
```

`bootstrap/modules.ts` 按依赖顺序实例化：

1. `settings`
2. `vault`
3. `folder`
4. `note`
5. `block`
6. `link`
7. `tag`
8. `search`
9. `indexer`
10. `graph`
11. `window`

每个模块返回统一形状：

```ts
export interface MainModule {
  id: string;
  migrations: Migration[];

export interface MainContext {
```

`bootstrap/ipc.ts` 只做汇总注册和 sender 校验；各模块的 `ipc/handlers.ts` 自己声明通道。

### 3.6 安全

- `app/create-window.ts` 固定 `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、`webSecurity: true`。
- Windows / Linux 使用 `frame: false` + `thickFrame: true` + `titleBarOverlay: false`；`app/menu.ts` 移除原生菜单栏；窗口控制由 `window` 模块提供 IPC，`shell/TitleBarControls.vue` 负责 UI。macOS 使用 `hiddenInset` 保留系统交通灯。
- `app/security.ts` 配置 CSP、拦截页面导航、外链只允许 `http` / `https` / `mailto` 并交给系统浏览器。
- `bootstrap/ipc.ts` 校验 sender frame，拒绝非主窗口来源。
- `preload` 只暴露白名单 API；渲染进程拿不到 `ipcRenderer`、`fs`、数据库连接。
- `platform/logger` 只写本地文件，不上传、不包含正文内容。

## 4. Preload

### 4.1 API 形态

```ts
// src/shared/contracts/api.ts
export interface EasyNoteApi {
  vault: VaultApi;
  folder: FolderApi;
  note: NoteApi;
  block: BlockApi;
  link: LinkApi;
  tag: TagApi;
  search: SearchApi;
  graph: GraphApi;
  settings: SettingsApi;
  window: WindowApi;
  events: EventsApi;
}
```

- `src/preload/api/<module>.ts` 只包含 `ipcRenderer.invoke` 包装与 `on / off` 订阅。
- `src/preload/api/index.ts` 汇总成 `EasyNoteApi`。
- `src/preload/index.ts` 通过 `contextBridge.exposeInMainWorld('easynote', api)` 暴露。
- `src/renderer/env.d.ts` 声明 `Window.easynote: EasyNoteApi`。

### 4.2 规则

- 不暴露通用 `invoke(channel, payload)`；每个能力一个显式方法。
- 不在 preload 做业务判断、数据转换、缓存。
- 所有 IPC 返回 `IpcResult<T>`；错误码定义在 `shared/contracts/errors.ts`，不抛裸异常。
- 事件订阅返回取消函数；渲染模块卸载时必须调用。
- 新增模块 API 时，只改 `api/<module>.ts` 与 `api/index.ts`，不改其他命名空间。

### 4.3 事件

`src/shared/contracts/events.ts` 维护跨模块事件：

| 事件 | 载荷 | 发出方 |
| --- | --- | --- |
| `vault:changed` | `vaultId`、路径 | `vault` |
| `folder:changed` | `folderId` | `folder` |
| `note:created` | `noteId` | `note` |
| `note:renamed` | `noteId`、新旧标题 | `note` |
| `note:deleted` | `noteId` | `note` |
| `note:external-change` | `noteId`、磁盘版本摘要 | `indexer` |
| `index:progress` | 阶段、当前、总数 | `indexer` |
| `index:updated` | 受影响笔记 ID | `indexer` |
| `window:maximized-changed` | `boolean` | `window` |
| `theme:changed` | `light` / `dark` | `platform/theme` |
| `settings:changed` | 变更键 | `settings` |

只加真正跨模块的事件；编辑输入的每一次变化留在编辑器本地，不走事件总线。

## 5. Renderer

### 5.1 模块分层

```
src/renderer/modules/<module>/
├─ components/        # 本模块 Vue 组件
├─ composables/       # 本模块交互逻辑
├─ stores/            # 本模块状态；不建全局大 store
├─ styles/            # 仅本模块样式
└─ index.ts           # install<Module> + 注册扩展点
```

- 模块不直接 import `window.easynote`，统一使用 `RendererContext.api`。
- 模块不 import 其他模块的 `components/`、`stores/`、`composables/`。
- 跨模块协作走 shell 扩展点、`RendererContext` 服务或 `events`。
- 通用 UI 组件放 `renderer/ui`；业务组件留在模块内。

```ts
export interface RendererContext {
```

### 5.2 模块清单

| 模块 | 视图 / 职责 | 注册到 |
| --- | --- | --- |
| `shell` | 应用外壳、顶栏、状态栏、标题栏控制、面板 host、主题 | 根组件 |
| `explorer` | 左侧文件树、新建、拖拽、右键菜单 | `sidebar` |
| `tags` | 左侧标签视图、多选过滤、AND / OR | `sidebar` |

| `backlinks` | 右侧反向链接 Tab | `rightPanel` |
| `outline` | 右侧大纲 Tab | `rightPanel` |

| `ui` | 按钮、输入框、菜单、对话框、Tooltip、Toast、图标 | 无业务注册 |

### 5.3 Shell 扩展点

`shell/registry/shell-registry.ts` 提供注册表，新模块不修改 shell 内部：

```ts
export interface ShellRegistry {
  sidebar: { registerView(view: SidebarView): void };
  workspace: { registerView(view: WorkspaceView): void };
  rightPanel: { registerTab(tab: RightPanelTab): void };
  status: { registerItem(item: StatusItem): void };
  overlay: { register(id: string, component: Component): void };
}
```

- 顶栏不开放注册。侧栏开关、面包屑、源码切换、主题、设置、右栏开关、窗口控制保持固定，避免再次把所有按钮堆到一页。
- 新模块优先注册为侧栏视图、右侧 Tab、状态项或独立浮层；不要默认加顶栏按钮。
- `shell` 提供 `ShellService`：布局开合、主题设置、面板宽度、当前视图。`settings` 等模块通过 `RendererContext.shell` 调用，不直接改 shell store。
- 安装顺序：`shell` 先安装，其他模块后安装；未注册的视图不占位。

### 5.4 UI 基础组件

`renderer/ui` 只放与业务无关的组件：

- `BaseButton`、`BaseInput`、`BaseMenu`、`BaseDialog`、`BaseTooltip`、`BaseTabs`、`BaseTree`、`ToastHost`。
- `icons/Icon.vue` 统一 16px 线性图标，图标名集中在 `paths.ts`；不使用 emoji、不引入彩色图标库。
- 设计 Token 在 `styles/tokens.css`、`styles/themes.css` 落地；模块样式使用 CSS 变量，不写死色值。
- 基础组件不 import 任何 feature module；feature module 可以 import `ui`。

### 5.5 状态与数据流

- `shell-store` 只放外壳状态：面板宽度 / 开合、当前 workspace 视图、主题、保存状态。
- 各模块自管业务状态：文件树展开、编辑器文档、搜索查询、图谱视图。
- 编辑器保存链路：`editor` 生成 Markdown → `api.note.save` → 主进程原子写入 → `indexer` 重建该笔记索引 → `index:updated` → `backlinks` / `tags` / `search` 失效重查。
- 外部文件变更：`indexer` 发出 `note:external-change` → `editor` 顶部显示非阻断横幅。
- 换库：`vault` 关闭旧连接、初始化新库，发出 `vault:changed`；`indexer` 停止旧 watcher，各模块清空缓存。
- 主题：`settings` 写入选择 → `platform/theme` 或设置事件 → `shell` 应用 `data-theme`，代码、公式、图谱同步换色。
- 标题栏：Windows / Linux 由 `shell/TitleBarControls.vue` 自绘最小化 / 最大化 / 关闭，拖拽区与 `no-drag` 按 UI 规范；macOS 不在窗口内重复绘制交通灯。

## 6. Shared

### 6.1 contracts

`src/shared/contracts` 是跨进程唯一契约层：

- `<module>.ts`：DTO、请求 / 响应类型、IPC 通道常量、模块错误码。
- `envelope.ts`：`IpcResult<T>` 与错误形状。
- `api.ts`：`EasyNoteApi` 汇总。
- `events.ts`：事件名与载荷。
- `errors.ts`：错误码联合类型。
- 所有 DTO 必须可结构化克隆：只含普通对象、数组、字符串、数字、布尔、null；日期用 ISO 字符串；不传类实例、函数、`Map` / `Set`。
- 渲染进程使用 DTO；主进程 domain entity 不直接穿过 IPC。

### 6.2 types / utils

- `types/brand.ts`：`NoteId`、`FolderId`、`BlockId` 等 branded string。
- `types/result.ts`：通用 `Result` 类型。
- `utils/text.ts`：纯文本归一化、字数口径等无副作用函数。
- `utils/date.ts`：ISO 时间格式化。
- `shared` 不 import `main`、`preload`、`renderer`，不 import Electron / Node。

### 6.3 文案

- UI 文案集中在 `renderer/i18n/zh-CN.ts`，组件内不硬编码中文。
- 主进程只返回错误码与兜底 message；面向用户的文案由渲染进程映射。
- 新增模块的文案 key 使用 `<module>.<section>.<name>`，如 `explorer.menu.newNote`。

## 8. 依赖规则

### 8.1 允许方向

| 从 | 可以依赖 | 禁止依赖 |
| --- | --- | --- |
| `shared` | 无 | `main`、`preload`、`renderer`、Electron、Node |
| `main/platform` | `shared` | 任何 feature module |
| `main/modules/*` | `shared`、`platform`、其他模块的 `index.ts` | 其他模块的 `domain/application/infrastructure/ipc`、`renderer` |
| `preload` | `shared` | `main`、`renderer` |
| `renderer/ui` | `shared`、`styles` | 任何 feature module |
| `renderer/modules/*` | `shared`、`ui`、`app`、`preload` 暴露的 API | 其他 feature 的内部组件 / store / composable、`main`、Electron、Node |
| `bootstrap` / `renderer/app` | 全部 | 无（组合根例外） |

### 8.2 硬禁止

- 渲染进程 import `electron`、`node:*`、`better-sqlite3`、`chokidar`、`fs`、`path`。
- 主进程 import `renderer` 或 Vue 组件。
- `preload` 包含业务逻辑或直接读写 SQLite / 文件。
- feature module import 其他模块的 `infrastructure` 或 repository。
- `platform` import feature module。
- 在 `shared` 放业务实现、数据库访问、Electron API。
- 新增顶层 `src/utils`、`src/common`、`src/services` 大杂烩目录。

### 8.3 路径别名

| 别名 | 指向 |
| --- | --- |
| `@shared/*` | `src/shared/*` |
| `@main/*` | `src/main/*` |
| `@preload/*` | `src/preload/*` |
| `@renderer/*` | `src/renderer/*` |

不使用模糊的 `@/*`，避免跨进程误引用。

### 8.4 边界检查

`scripts/check-boundaries.mjs` 扫描 `src/**/*.{ts,vue}` 的 import，至少检查：

- 上面「硬禁止」全部规则。
- 模块间深层导入：`@main/modules/<a>/...` 只能到 `index`。
- `renderer/modules/<a>` 不得 import `renderer/modules/<b>` 内部文件。
- 循环依赖。
- `package.json` 的 `check` 脚本串联 typecheck、boundaries、tests。

## 9. 新增模块流程

### 9.1 步骤

1. 明确模块归属：主进程、渲染进程，还是两者都需要。
2. 在 `shared/contracts/<module>.ts` 定义 DTO、通道、错误码；在 `api.ts` 增加命名空间。
3. 主进程模块：按 §7.1 建目录，导出 `create<Module>Module`，在 `bootstrap/modules.ts` 注册。
4. 有数据库表：在模块 `infrastructure/migrations.ts` 声明迁移，在 `bootstrap/migrations.ts` 汇总。
5. 有 IPC：在模块 `ipc/handlers.ts` 注册；在 `preload/api/<module>.ts` 包一层，在 `preload/api/index.ts` 汇总。
6. 渲染模块：按 §7.2 建目录，在 `app/modules.ts` 注册；通过 shell registry 选择扩展点。
7. 增加测试：`tests/main/modules/<module>/` 和 / 或 `tests/renderer/modules/<module>/`。
8. 运行 `npm run check`，边界、类型、单测全过。

### 9.2 必须改的文件

| 文件 | 何时改 |
| --- | --- |
| `src/shared/contracts/<module>.ts` | 新建模块 |
| `src/shared/contracts/api.ts` | 新增渲染 API 命名空间 |
| `src/shared/contracts/events.ts` | 新增跨模块事件 |
| `src/main/modules/<module>/` | 主进程能力 |
| `src/main/bootstrap/modules.ts` | 注册主进程模块 |
| `src/main/bootstrap/migrations.ts` | 模块有表 |
| `src/preload/api/<module>.ts` | 新增 IPC 命名空间 |
| `src/preload/api/index.ts` | 汇总 API |
| `src/renderer/modules/<module>/` | 新增界面能力 |
| `src/renderer/app/modules.ts` | 注册渲染模块 |
| `tests/main/modules/<module>/`、`tests/renderer/modules/<module>/` | 新增行为测试 |

除上述组合根与契约文件外，不修改其他模块内部。

### 9.3 示例：未来块级历史（非首版）

1. 新建 `shared/contracts/history.ts`：`history:list`、`history:restore`。
2. 新建 `main/modules/history`：拥有 `block_history` 表，订阅 `note:saved`，按块记录快照。
3. `preload/api/history.ts` 暴露查询 / 恢复；`api/index.ts` 汇总。
4. 新建 `renderer/modules/history`：通过 `ctx.shell.registry.rightPanel.registerTab` 挂一个历史 Tab。
5. `app/modules.ts` 注册。
6. 不改 `note`、`indexer`、`editor` 内部；只在需要时让 `note` 发出 `note:saved`。

### 9.4 不要过早拆模块

- 只被一个模块使用的组件、composable、纯函数，留在该模块内。
- 通用 UI 进 `renderer/ui`；跨进程纯函数进 `shared/utils`；不要新建 `common` / `utils` 模块。
- 一个模块只承担一个业务能力；文件数超过约 15 个或出现两个无关键能力时再拆。
- 只有需要独立生命周期、独立数据所有权或明确扩展点时才新建模块。

## 10. 命名约定

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块目录 | kebab-case，主进程用单数领域名 | `note`、`folder`、`indexer` |
| 渲染视图模块 | 按视图命名 | `explorer`、`backlinks`、`quick-switch` |
| TS 文件 | kebab-case | `note-service.ts` |
| Vue 组件 | PascalCase | `FileTree.vue` |
| composable | `use` 前缀 | `useBlockDrag.ts` |
| store | `<module>-store.ts` | `editor-store.ts` |
| IPC 通道 | `<module>:<action>` | `note:save`、`link:backlinks` |
| 事件 | `<module>:<event>` | `note:renamed`、`index:updated` |
| 错误码 | `<MODULE>_<REASON>` | `NOTE_NOT_FOUND`、`VAULT_WRITE_DENIED` |
| 表名 | snake_case，复数 | `notes`、`note_tags`、`file_state` |
| 测试 | 与源码同名 + `.test.ts` / `.spec.ts` | `note-service.test.ts` |

- 模块公共 API 使用 named export；Vue SFC 的 default export 除外。
- 只有模块根目录允许 `index.ts` barrel；模块内部不再套 barrel。
- 禁止 `export *` 跨模块聚合，避免隐式循环依赖。
