# EasyNote Git 提交规范

适用范围：本仓库所有代码、文档、配置改动。

**每完成一个任务（功能、修复、重构、测试、文档、配置）且验证通过后，必须立即提交一次 Git，不得把多个任务积压到同一次提交。**

## 1. 提交前检查

```bash
git status --short
git diff --stat
```

- 优先运行覆盖本次改动的窄范围检查；脚手架就绪后至少运行 `npm run check`。
- 验证失败不得提交，先修复或如实报告阻塞。
- 确认没有混入无关格式化、调试输出、临时文件。

## 2. 暂存

- 只暂存本任务相关文件，逐路径执行 `git add <path>`。
- 禁止用 `git add -A` 代替审查。
- 不得提交：`node_modules/`、`dist/`、`out/`、`release/`、`coverage/`、`.easynote/`、日志、密钥、`.env`、用户库内容。
- 钩子或检查失败时修复问题，禁止 `--no-verify` 绕过。

## 3. 提交信息

采用 Conventional Commits。摘要用中文、动词开头、不超过 50 字：

```
<type>(<scope>): <摘要>

<可选：动机与影响>
<可选：验证方式>
```

| type | 用途 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `refactor` | 不改变行为的重构 |
| `perf` | 性能优化 |
| `test` | 测试 |
| `docs` | 文档 |
| `build` | 构建 / 依赖 |
| `ci` | CI 配置 |
| `chore` | 其他维护 |

`scope` 使用模块或目录名，如 `note`、`editor`、`indexer`、`docs`、`repo`。

示例：

```
feat(note): 增加重命名标题冲突处理
fix(indexer): 避免 watcher 重建时重复入队
docs(git): 增加任务完成后的提交规范
chore(repo): 初始化仓库并纳入项目文档
```

## 4. 提交后

```bash
git log -1 --oneline
```

- 在结果中报告提交哈希与摘要。
- 一个任务一个提交；用户明确要求不提交时，遵从用户。
- 不修改已推送提交的历史；需要补充时追加新提交。

## 5. 禁止事项

- 多个任务合并为一次提交。
- 提交构建产物、依赖目录、本地库、日志、密钥。
- 使用 `--no-verify` 跳过钩子。
- 未经审查的 `git add -A`。
- 重写已推送的提交历史。
